## 1. 스프링부트 테스트란 무엇인가요? (기본 개념 잡기)

스프링부트 애플리케이션은 계층(Layer) 구조로 이루어져 있습니다:
`Controller (웹 요청 수신)` ➔ `Service (비즈니스 로직)` ➔ `Repository (DB 통신)` ➔ `Database`

테스트는 크게 세 가지 방식으로 진행합니다:

```text
┌─────────────────────────────────────────────────────────────┐
│ 1. 단위 테스트 (Unit Test)                                  │
│    - 다른 부품(DB, 웹) 없이 Service 로직만 빠르게 단독 검증   │
│    - Mockito(가짜 객체)를 사용해 'DB에 저장되었다고 치고' 테스트│
├─────────────────────────────────────────────────────────────┤
│ 2. 컨트롤러 테스트 (MockMvc Slice Test)                      │
│    - URL 경로, HTTP 응답코드(200, 201, 400), JSON 형식을 검증  │
├─────────────────────────────────────────────────────────────┤
│ 3. 실서버 수동 테스트 (Swagger UI / H2 Console)              │
│    - 서버를 직접 켜고 웹 브라우저에서 마우스로 클릭하며 검증  │
└─────────────────────────────────────────────────────────────┘
```

## 3. 실습 1: 자동화 테스트 실행해보기 (가장 쉬운 방법)

### 방법 A: 터미널에서 전체 테스트 한번에 돌리기
프로젝트 루트 경로(`d:\yearly-goal-tracker\yearly-goal-tracker`)의 터미널에서 아래 명령어를 입력합니다.

```powershell
./gradlew test
```

- 실행 결과 맨 마지막에 `BUILD SUCCESSFUL` 문구가 나오면 모든 테스트가 통과된 것입니다.
- **예쁜 시각화 보고서 보기**:
  파일 탐색기에서 `d:\yearly-goal-tracker\yearly-goal-tracker\build\reports\tests\test\index.html` 파일을 더블클릭하여 웹 브라우저(Chrome/Edge)로 열어보세요. 모든 테스트의 성공률(100%)과 수행 시간이 초록색 그래프로 표시됩니다.

### 방법 B: IDE(VS Code)에서 클릭으로 돌리기
1. 좌측 탐색기에서 `src/test/java/com/hoeseok/yearly_goal_tracker/service/GoalServiceTest.java` 파일을 엽니다.
2. `class GoalServiceTest` 옆이나 각 `@Test` 메서드 옆에 있는 **초록색 재생(▶) 아이콘**을 클릭합니다.
3. 테스트가 성공하면 초록색 체크(✔) 표시가 뜹니다.

## 4. 실습 2: 서버 켜고 Swagger UI로 웹에서 직접 테스트하기 (강력 추천!)

Swagger는 브라우저에서 마우스 클릭만으로 API를 호출해볼 수 있는 대화형 웹 인터페이스입니다.

### 1단계: 서버 실행하기
터미널에서 아래 명령어를 실행합니다:
```powershell
./gradlew bootRun
```
*(콘솔에 `Started YearlyGoalTrackerApplication in ... seconds`가 뜨면 서버가 켜진 상태입니다.)*

### 2단계: 웹 브라우저 접속
크롬이나 엣지 브라우저 주소창에 아래 주소를 입력합니다:
👉 **[http://localhost:8080/swagger-ui/index.html](http://localhost:8080/swagger-ui/index.html)**

---

### 3단계: 실제 데이터를 넣는 실습 순서 (시나리오)

Swagger 화면에서 각 API를 클릭하고 **[Try it out]** ➔ 내용 입력 ➔ **[Execute]** 버튼을 순서대로 눌러보세요!

#### ① 사용자 등록
- **API**: `POST /api/v1/users`
- **Request Body 입력**:
  ```json
  {
    "email": "hoeseok@example.com",
    "username": "정회석"
  }
  ```
- **[Execute] 클릭**: Response Body에 `"id": 1`이 포함된 성공 JSON(`201 Created`)이 반환됩니다.

#### ② 연간 목표 등록
- **API**: `POST /api/v1/goals`
- **Request Body 입력**:
  ```json
  {
    "userId": 1,
    "title": "2026 정보처리기사 자격증 취득",
    "description": "올해 안에 필기/실기 동차 합격하기",
    "category": "STUDY",
    "startDate": "2026-01-01",
    "endDate": "2026-12-31",
    "targetProgressRate": 100
  }
  ```
- **[Execute] 클릭**: 목표 ID `1`번이 생성됩니다.

#### ③ 하위 태스크 등록
- **API**: `POST /api/v1/goals/{goalId}/sub-tasks`
- **goalId**: `1`
- **Request Body 입력**:
  ```json
  {
    "title": "매주 모의고사 1회 풀기",
    "periodType": "WEEKLY",
    "targetCount": 1
  }
  ```
- **[Execute] 클릭**: 하위 태스크 ID `1`번이 생성됩니다.

#### ④ 오늘 체크인 등록
- **API**: `POST /api/v1/sub-tasks/{subTaskId}/check-ins`
- **subTaskId**: `1`
- **Request Body 입력**:
  ```json
  {
    "checkInDate": "2026-08-30",
    "status": "SUCCESS",
    "progressRate": 100,
    "memo": "1회차 모의고사 85점 달성!"
  }
  ```
- **[Execute] 클릭**: 체크인이 성공적으로 저장됩니다.

#### ⑤ 목표 상세 조회 (모든 게 잘 연결되었는지 확인)
- **API**: `GET /api/v1/goals/{id}`
- **id**: `1`
- **[Execute] 클릭**: 목표 정보 아래에 우리가 등록한 `subTasks` 목록이 포함되어 깔끔하게 출력되는 것을 확인할 수 있습니다!

#### ⑥ 예외(실패) 테스트도 해보기!
- 같은 날짜(`2026-08-30`)로 ④번 체크인을 한 번 더 [Execute] 해보세요.
- ➔ `409 Conflict`와 함께 `"해당 날짜에 이미 체크인 기록이 존재합니다."`라는 에러 메시지가 정확히 반환되는 것을 확인할 수 있습니다.

## 5. 실습 3: H2 Console로 DB 테이블 직접 들여다보기

서버가 켜져 있는 상태에서 DB에 실제로 테이블이 어떻게 만들어지고 데이터가 들어갔는지 눈으로 볼 수 있습니다.

1. 브라우저에서 👉 **[http://localhost:8080/h2-console](http://localhost:8080/h2-console)** 접속
2. 설정값 확인:
   - **JDBC URL**: `jdbc:h2:mem:yearlydb`
   - **User Name**: `sa`
   - **Password**: *(빈칸)*
3. **[Connect]** 클릭
4. 왼쪽 창에 `USERS`, `GOALS`, `SUB_TASKS`, `CHECK_INS` 테이블이 보입니다.
5. `SELECT * FROM GOALS;`를 입력하고 상단의 **[Run]**을 누르면 DB에 방금 넣은 데이터 행이 조회됩니다.

## 6. 초보자를 위한 꿀팁 & 주의사항

1. **서버 재시작 시 데이터**:
   - 현재 로컬 개발 환경은 `H2 In-Memory DB`(`jdbc:h2:mem:yearlydb`)를 사용하므로, **서버를 껐다 켜면 데이터가 초기화**됩니다. (자동 테스트가 항상 깨끗한 상태에서 돌 수 있는 장점이 있습니다.)
2. **서버 끄는 방법**:
   - `./gradlew bootRun`이 실행 중인 터미널에서 `Ctrl + C`를 누르면 서버가 안전하게 종료됩니다.
3. **코드 수정 후 재테스트**:
   - 비즈니스 로직을 변경했을 때는 항상 `./gradlew test`를 먼저 돌려 기존 기능이 깨지지 않았는지 확인하는 습관을 들이면 좋습니다.
