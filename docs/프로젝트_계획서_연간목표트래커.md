# 프로젝트 계획서: 연간 목표 트래커 (가칭 "Yearly")

작성일: 2026-08-30
작성자: 정회석

---

## 1. 프로젝트 개요

### 1.1 배경 및 목적
1년 단위의 장기 계획(자격증 취득, 이직 준비, 운동, 독서 등)을 세워도 중간에 흐지부지되는 경우가 많다. 특히 "계획을 어겼을 때" 스스로 인지하지 못하고 넘어가는 게 가장 큰 문제. 이를 해결하기 위해 **연간 계획을 세분화하여 등록하고, 진행 상황을 체크하며, 계획을 지키지 않았을 때 알림을 받는** 개인용 웹 서비스를 만든다.

### 1.2 프로젝트 목표
- 스프링부트 기반 백엔드 개발 경험 축적 (첫 사이드 프로젝트)
- 실제로 본인이 사용할 수 있는 실용적인 도구 완성
- 배치/스케줄러, 알림 발송, 인증 등 실무형 기능을 직접 구현해보며 학습

### 1.3 대상 사용자
1차 목표: 본인(1인 사용) → 추후 지인 공유 또는 다중 사용자 확장 가능하도록 설계

## 2. 핵심 기능 정의

### 2.1 계획(목표) 관리
| 기능 | 설명 |
|---|---|
| 연간 목표 등록 | 목표명, 카테고리(자격증/운동/재테크/독서 등), 시작일~종료일, 목표 수치(선택) |
| 목표 세분화 | 연간 목표 → 분기/월간/주간 단위 하위 태스크로 쪼개기 |
| 진행 체크 | 일/주/월 단위로 "완료 여부" 또는 "진척률(%)" 입력 |
| 목표 상태 | 진행중 / 지연 / 완료 / 중단 |

### 2.2 미이행 감지 및 알림 (핵심 기능)
| 기능 | 설명 |
|---|---|
| 이행 규칙 설정 | 예: "매주 3회 이상 체크인 필요", "월말까지 진척률 80% 이상" |
| 스케줄러 배치 | 매일 자정 배치 실행 → 규칙 대비 미이행 항목 탐지 |
| 알림 발송 | 이메일(1차) → 추후 슬랙/텔레그램/푸시 확장 |
| 알림 유형 | ① 마감 임박 리마인드 ② 규칙 미달성 경고 ③ 장기 미접속 경고 |
| 알림 이력 | 발송된 알림 로그 조회 |

### 2.3 대시보드/뷰
| 화면 | 설명 |
|---|---|
| 연간 개요 뷰 | 12개월 타임라인에 목표별 진행률 시각화 (간트차트 느낌) |
| 목표 상세 뷰 | 하위 태스크 목록, 체크인 히스토리, 그래프 |
| 오늘의 체크인 뷰 | 오늘 해야 할 항목만 모아서 빠르게 체크 |
| 통계 뷰 | 카테고리별 달성률, 월별 추이 |
| 알림 설정 뷰 | 목표별 알림 규칙 커스터마이징 |

### 2.4 인증/기타
- 로그인/회원가입 (1인 사용이면 단순 로그인 또는 스킵 가능, 확장 고려해 JWT 기반으로 설계)
- 마이페이지 (알림 채널 등록: 이메일 주소 등)

## 3. 기술 스택 (제안)

| 영역 | 기술 | 비고 |
|---|---|---|
| Backend | Spring Boot 3.x, Java 17+ | |
| ORM | Spring Data JPA + Hibernate | |
| DB | PostgreSQL (또는 개발단계 H2) | |
| 스케줄링 | Spring Scheduler (`@Scheduled`) → 추후 Quartz 확장 | 미이행 감지 배치용 |
| 알림 발송 | Spring Mail (SMTP) | 이후 슬랙 Webhook, 텔레그램 Bot API 확장 |
| 인증 | Spring Security + JWT | |
| Frontend | React (또는 Thymeleaf로 단순 시작 후 React 전환) | 본인 프론트 경험 따라 선택 |
| 배포 | Docker + (AWS EC2/RDS 또는 Free Tier 활용) | AWS SAA 학습과 연계 가능 |
| 형상관리 | GitHub | Antigravity IDE 연동 |

> 참고: AWS SAA-C03 준비 중이시니, 배포 단계에서 EC2/RDS/S3 등을 직접 써보면 학습 시너지가 큼.

## 4. 데이터 모델 개요 (초안)

```
User (사용자)
 └─ Goal (연간 목표)
     ├─ category, title, start_date, end_date, target_status
     └─ SubTask (하위 태스크: 분기/월/주 단위)
         └─ CheckIn (체크인 기록: date, status, progress_rate)
     └─ NotificationRule (알림 규칙: type, condition, channel)
         └─ NotificationLog (발송 이력)
```

## 5. 개발 일정 (마일스톤)

| 단계 | 기간(예상) | 내용 |
|---|---|---|
| 1단계: 설계 | 1~2주 | 요구사항 확정, ERD 설계, 화면 와이어프레임 |
| 2단계: 기본 CRUD | 2~3주 | 목표/태스크/체크인 등록·조회·수정·삭제, 인증 |
| 3단계: 알림 배치 | 2주 | 스케줄러 구현, 미이행 감지 로직, 이메일 발송 |
| 4단계: 대시보드 뷰 | 2~3주 | 연간 타임라인, 통계 화면 (프론트 연동) |
| 5단계: 배포 | 1주 | Docker화, 클라우드 배포 |
| 6단계: 고도화 | 지속 | 슬랙/텔레그램 알림, 다중 사용자, 모바일 대응 |

*첫 사이드 프로젝트이므로 각 단계 기간은 여유 있게 잡았습니다. 실제로는 퇴근 후/주말 작업 기준으로 조정 필요.*
